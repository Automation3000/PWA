Tabreed Automation App

A comprehensive, offline-first Progressive Web Application (PWA) and industrial control portal built for district cooling automation engineers, supervisors, and plant technicians. Designed to streamline work orders, instrument lookups, plant navigation, and operational audits.

Architecture: Full-Stack Express + PWA SPA Cloud Target: Cloud Run (Node.js ESM) Database: Google Sheets (GAS) + Local Cache Port: 3000 (Reverse Proxy Safe) Offline Tier: Service Worker v17 + LocalStorage Queue

⚡ Offline-First Design

Operates with zero internet connectivity. All static bundles are cached via Service Worker, while data mutations queue in LocalStorage and sync automatically once network reconnects.

🔄 2-Way Cloud Sync

Bi-directional communication between client devices and Google Sheets via Google Apps Script (GAS) Web Apps, buffered through an intelligent Express proxy.

🛡️ Strict Audit & RBAC

Role-based access control (User, Supervisor, Super-Admin 41764). Built-in audit trail with deduplication and 24-hour timestamps attributing real user names.

End-to-End Data Flow Pipelines

1. Work Order Request Submission & 2-Way Sync
Step 01: Client Input saveRequest() User fills Work Order, Plant, Date, 24-hr Time & Team. Form computes audit diff if editing.
Step 02: Optimistic UI LocalStorage Cache New/edited item is immediately saved into LS_REQUESTS. UI renders without waiting for network.
Step 03: Express Proxy POST /api/operation-requests Payload carries skipAutoHistory:true and logged-in user name. Proxy writes to local JSON fallback.
Step 04: Google Sheet Operation_Request_GAS GAS script updates row in Google Sheet. Avoids duplicate log creation due to skipAutoHistory flag.
2. Status Update & Deduplicated Audit Logging
Step 01: Supervisor Action saveInlineStatus() Supervisor changes status via inline dropdown (e.g. Requested → Pending). Verifies role authorization.
Step 02: Real-User Log logOperationActivity() Frontend records activity with actual technician/supervisor name (e.g. Majeed) rather than generic label.
Step 03: Server Deduplication deduplicateHistoryList() Collapses concurrent entries within 5-min window, standardizes to 24-hr DD.MM.YYYY HH:mm, prioritizes named user.
Step 04: Audit History operation_history.json Stored in descending chronological order. Re-rendered instantly in History modal with filter tabs.
3. Offline-First Resilience & Background Sync
Step 01: Offline Detection navigator.onLine = false App switches to offline mode with top status badge. Network mutations enter tabreed_sync_queue.
Step 02: Service Worker Cache tabreed-pro-v17 All HTML, stylesheets, scripts and cached JSON data serve instantly from Cache Storage.
Step 03: Reconnect Event window 'online' Event Service Worker fires sync trigger; client triggers syncOfflineQueue().
Step 04: Batch Flush POST batchSync Queued mutations execute sequentially with retry limits, purging resolved queue items on success.
4. Server-Side Gemini API / AI Logic Gateway
Step 01: Secure Architecture Zero Client Secrets Client UI never stores API keys. All AI operations are proxied through server-side /api/* routes.
Step 02: Server Invocation @google/genai SDK Node.js server uses the official Google GenAI SDK initialized lazily with Cloud environment variables.
Step 03: Model Execution gemini-2.5-flash Processes operations summarization, checklist validation, and diagnostic prompts with low latency.
Step 04: Sanitized Response JSON Payload Return Structured insights return to client UI for non-blocking rendering.

Backend Server & Proxy Layer (server.js)

Architecture Role

server.js is an ES-module Node.js Express server running on port 3000. It acts as both the static file host and an intelligent, fault-tolerant proxy between the PWA clients and Google Apps Script Web Apps.

Function / Component Type Technical Description & Guarantees
appsScriptProxy Proxy Handler Forwards requests to GAS with custom headers, 12s timeout, 3-retry exponential backoff, and fallback to local JSON file when cloud is unreachable.
deduplicateHistoryList() Data Engine Normalizes actions ('create', 'update', 'status'), parses timestamps into epoch ms, formats to 24-hr strings, and merges duplicate entries within 5 minutes.
format24HourDateTime() Formatter Converts epoch ms to strict DD.MM.YYYY HH:mm 24-hour time format with zero padding.
loadHistoryData() / saveHistoryData() Persistence Maintains local disk cache in operation_history.json with thread-safe atomic file writes.
loadRequestsData() / saveRequestsData() Persistence Maintains persistent local copy of requests in operation_requests.json for offline fast boot.

Operation Request Module (Operation_Request.html & GAS)

Operation_Request.html

Single-page application handling the entire lifecycle of industrial work order requests:

  • Creator Edit Actions: canUserEditRequest(req) permits logged-in users who created or are listed on a request to edit their own entry directly via an "Edit" button in the Action column.
  • Supervisor Controls: Full status change dropdown, WhatsApp message generator, archive toggle, Excel/PDF export, delete confirmation modal.
  • 24-Hour Time Picker: Built-in minimal time selector modal supporting strict 24-hr industrial formats.
  • Live Search & Filters: Filter by WO#, Plant ID, status pills (All, Requested, Pending, In Progress, Completed, Cancelled).
  • Audit Trail: In-modal history view showing exact diff changes, who edited the request, and timestamps.

Operation_Request_GAS.gs.txt

Google Apps Script backend deployed as a Web App to interact with Google Sheets:

  • doGet(e): Fetches all requests from the 'Operation Request' sheet and history logs from 'History' sheet.
  • doPost(e): Dispatches actions: create, update, updateStatus, delete, batchSync.
  • skipAutoHistory Guard: Prevents duplicate entry generation by verifying !data.skipAutoHistory && !data.skipHistoryLog before calling logToHistorySheet().
  • Auto-Indexing: Maintains Work Order identifiers and row index pointers for rapid lookup.

ETS Locator Architecture (ETS_Locator.html & GAS)

ETS Locator Features

Energy Transfer Station (ETS) navigation and mapping assistant for field service technicians:

  • Plant Search: Instant fuzzy filtering by ETS code (e.g. AD-032), Customer Name, Sector, or Plant Type.
  • Navigation Links: Direct deep-linking to Google Maps GPS navigation using plant latitude and longitude coordinates.
  • Offline Storage: Complete ETS directory cached locally for remote plant basements without cellular signal.

Backend Setup (ETS_Locator_GAS.gs.txt)

Google Apps Script script that queries the central plant inventory spreadsheet:

  • Returns structured JSON with headers: Plant ID, Name, Customer, Latitude, Longitude, Status.
  • Cached in browser via IndexedDB/LocalStorage with automatic sync triggers on reconnection.

Authentication & Role-Based Access Control (RBAC)

The application uses a lightweight, resilient authentication system defined in employees.json with three functional privilege tiers:

Role Tier Identifiers Privileges & Visible Actions
Super Admin / Developer Code: 41764 (Majeed) Full system unlock: Developer Tools tile grid, PingLogger, System Logs, Cache Reset, Broadcast Notifications, Beta Theme Switcher, Full Data Export (Excel/PDF), and unconstrained record editing.
Supervisor Role: supervisor (e.g. Bibin 40078) Status dropdown mutation (Inline status updates), Work Order deletion with confirmation modal, request archiving/unarchiving, Excel/PDF export, full audit trail visibility.
Field Technician / Creator Standard Employee Codes (e.g. 40311, 40334, 40659) Submit work order requests, view plant catalogs and contacts. When logged in, Edit button is enabled exclusively for requests created by or assigned to them.

Service Worker (sw.js v17) & PWA Offline Engine

Caching Strategy

sw.js enforces dual cache policies to balance real-time freshness and offline resilience:

  • HTML Documents: Network-First with Cache Fallback — Guarantees users always see the latest UI deployments when online, while falling back gracefully to cached pages when offline.
  • Static Assets (CSS, JS, Icons): Cache-First with Background Revalidation — Instant load times with zero network overhead.
  • API Exemption: /api/ and script.google.com bypass Service Worker fetch interception to allow native browser queuing.

Native Installation Profiles

Configured for zero-friction mobile deployment across all operating systems:

  • manifest.json: Standalone display mode, high-res PWA icons (72x72 through 512x512), theme color #1a73e8.
  • Automation.mobileconfig: Apple iOS WebClip profile enabling direct home screen installation on iPhones without App Store restrictions.
